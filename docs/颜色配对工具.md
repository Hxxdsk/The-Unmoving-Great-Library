# 商品图片 · 颜色配对助手

中文桌面程序。读取商品资料 Excel，以 **供应商款式编码** 分款，用 Gemini 比较颜色图与商品原图，人工确认对应关系后，为每个商品编码复制一张图片。

## Windows 使用

1. 安装 可运行依赖的 Python（已验证 Python 3.14），安装时勾选 Add Python to PATH。
2. 解压程序包，双击 **启动工具箱.exe**。首次运行会联网安装依赖；之后使用同一个虚拟环境。
3. 点击 **选择目录**，选择同时包含表格和款号文件夹的目录。若有多个表格，选择正确的表格，再点击 **读取表格**。
4. 粘贴自己的 **Gemini API Key**，点击 **检测模型**，选择模型。下次打开会显示上次选择，检测后恢复其可用状态；Key 只在本次运行的内存中使用。
5. 点击 **AI 识别全部款号**。也可重识别当前款号。检查配对表、缩略图，点击下方原图或双击配对行放大查看。
6. 对未匹配或需要调整的颜色，在 **使用的原图** 下拉框中选择对应图片，即完成手动连接。所有颜色均选好后点击 **确认配对并输出图片**。

程序不会下载表格中的远程图片 URL；它使用你本地款号文件夹里的原图。AI 会向 Google Gemini 发送颜色图与商品原图的压缩副本，以及原图文件名；不会发送整张 Excel、商品编码或其他表格列。图片里的文字与表格数据只作为待分析内容，不作为程序指令。

## 目录与表格

```text
聚水潭图片/
├─ 商品资料.xlsx
├─ CYMY9692/
│  ├─ 颜色.png          # 也支持颜色.jpg / .jpeg / .webp 等
│  ├─ 1.jpg
│  ├─ 2.jpg
│  └─ ...
└─ 其他供应商款号/
   ├─ 颜色.jpg
   └─ ...
```

- 表格必须包含 `供应商款式编码`、`颜色`、`商品编码` 三列，列顺序不限；扫描所有工作表前 30 行寻找表头。
- 支持 `.xlsx`、`.xlsm`；旧 `.xls` 请先另存为 `.xlsx`。
- 根据供应商款式编码找所选目录下一层同名文件夹，忽略首尾空白、大小写和全半角差异；不按“款式编码”列找文件夹。
- 每个款号必须恰好有一张文件主体名为 `颜色` 的图片；其余图片都作为候选原图。支持 JPG、JPEG、PNG、WEBP、BMP、TIF、TIFF、GIF（动画只分析第一帧，输出保留原文件）。
- ERP 导出表格错误的 `A1:A1` 尺寸标记也能正常读取，上传的商品资料表格属于这种情况。
- 完全重复的商品编码会合并并记录提醒。商品编码被分配给不同款号或颜色、必填字段为空、文件名不合法时，会停止读取并指出问题。

## 配对与输出

AI 分两步工作：先识别颜色总览图里的名称与主体颜色，再逐张比较商品图片的主体颜色与总览图。它不依赖图片顺序、文件序号或衣服姿势。

颜色图与表格名称相同（允许 `浅灰` / `浅灰色` 这样的“色”字差异），且 AI 自评可信度至少 88%、没有标记不确定时，自动建议一张原图。同色有多张图时选可信度最高的一张，所有尺码共用这张。**可信度是模型自评，不是准确率保证，自动结果也应核对。**

表格 `深灰色` 与图中 `花灰色` 不会按近似名称自动连接。你可在表格 `深灰色` 行选择显示 `花灰色` 的原图。不同表格颜色也允许选择同一张原图。人工选择在重识别时保留。

例如 `黑色 → 2.jpg` 对应六个商品编码时，会复制原始 `2.jpg` 为：

```text
_商品编码图片/20261013_143000_随机批次号/CYMY9692/
  DKU264MWM1246-DY0201.jpg
  DKU264MWM1246-DY0202.jpg
  DKU264MWM1246-DY0203.jpg
  DKU264MWM1246-DY0204.jpg
  DKU264MWM1246-DY0205.jpg
  DKU264MWM1246-DY0206.jpg
```

输出保留原图字节与格式，原图和表格保持不变。每次输出使用新批次目录，不覆盖以前结果；失败或取消会清理本批次临时文件。批次内附 `配对记录.csv`（可用 Excel 打开）和 `配对记录.json`，记录款号、表格颜色、商品编码、原图路径、输出文件与 SHA256。

未选好全部颜色或存在缺失款号文件夹时，输出按钮不会启用。AI 失败的款号会显示错误；其他款号继续识别。若图片已经足够明确，可以不调用 API，直接人工选择全部颜色后输出。

## Gemini 模型和网络

通过 Google 官方 `v1beta/models` API，分页检测该 Key 可见、支持 `generateContent` 的 Gemini 模型，排除明确的嵌入、图像生成和语音模型。列表可见并不保证该模型接受图片、结构化 JSON 或当前有剩余额度；这些能力在实际识别时验证。失败会显示错误，可以改用其他模型，不会伪造识别结果。

网络须可通过 HTTPS 访问 **generativelanguage.googleapis.com**。默认系统代理配置生效，TLS 验证保持启用。限流与暂时性服务器错误最多重试两次；每次网络请求最长等待 90 秒。取消会阻止下一次请求，正在发出的请求需等待响应或超时。

模型、上次目录及表格名称保存在系统应用配置目录下的 `GreatLibrary/ColorImageAssistant/preferences.json`（实际路径由 Qt 按系统决定）。不保存 API Key。程序不要求把 Key 写入代码、配置或表格。

## 集成版启动

当前程序已集成到“大图书馆工具箱”，首页点击“商品图片颜色配对”打开此独立工具。Windows 原生启动器的代码在 `launcher/`，构建方法见项目 README。

## 开发与验证

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python suite_entry.py --tool color
```

Linux 需要图形桌面才能交互使用，云机器可用 offscreen 模式验证界面。

```bash
.venv/bin/python -m pip install pytest
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
```

测试覆盖表格读取、ERP 尺寸异常、多款号、颜色名称与人工配对、模型分页、识别响应校验、API 错误与取消、复制完整性、重复批次、输出失败清理和桌面界面工作流。模拟 Gemini 响应只验证集成流程，不代表真实识别准确率。真实效果需要用自己的 API Key 和原始商品图片运行。
